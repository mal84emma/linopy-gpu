**The interlock that makes these numbers defensible** (carried verbatim from plan-3 §8.5, whose
argument this freeze adopts):

> These numbers are only valid because linopy defaults `method=3` (Barrier). Exploration §7 showed
> cuOpt's default `1e-4` tolerances moving an objective by `5.52e-03` relative on a 2000×1000 LP
> under **PDLP**, and the four methods disagreeing by `2.5e-5` relative on an n=5000 model at
> default tolerances. Therefore:
> * **No test may force `method=1` (PDLP) and then assert against these tolerances.**
> * **No test tightens cuOpt's own tolerance parameters.** If a differential check misses, the
>   honest outcome is a reported miss with the actual numbers, **not** an injected
>   `set_optimality_tolerance` and **not** a widened `rtol` (I12, §3.6).
> * If WP-A's contingency (FINAL.md §5b) forces the default method away from Barrier, **every
>   tolerance in this table must be re-derived at Gate 3 before it is frozen.** That dependency is
>   stated here so it cannot be lost.

**Pre-decided contingencies** are frozen in `FINAL.md` §8.5 and are part of this freeze. Any miss
not covered there is reported verbatim, with actual numbers, and work stops on that item.

| anything else | `unknown` | not forced — the `.get(..., unknown)` default; asserted by a unit call on the map dicts with a synthetic key | `test/test_cuopt.py::test_status_map_default` |

Two traps the tests must honour, both measured:

* **A limit *setting* never implies a limit *status*.** `iteration_limit=1` on a knapsack returned
  `Optimal obj=-2020` (expl §1). No test infers a condition from the options it passed.
* **`ErrorStatus` is not a `TerminationCondition`.** It is read alongside and logged when non-zero
  (`ErrorStatus.Success == 0`). No test maps it to a condition.

## Nondeterminism

cuOpt is a concurrent, first-order-capable solver, so this section is not "None". Two distinct
sources, handled differently:

**1. The concurrent race (`method=0`) — excluded by construction, not by a statistical criterion.**
cuOpt's own default runs dual simplex, barrier and PDLP concurrently and reports the winner, which
can vary run to run. linopy defaults to `method=3` (Barrier), a **single** method, so no test in
this plan is exposed to the race. This is not merely a tolerance decision: `method=0` is a
deterministic SIGSEGV on the 2nd–3rd sequential solve above ~1300 variables (expl §9), which is why
V1-8 exists. **No test may set `method=0`**, and V1-8 is the check that a future change of default
cannot slip through silently.

**2. First-order / floating-point variation under the chosen default.** Under `method=3` the only
non-reproducible quantities are GPU reduction order and Barrier's own convergence point. Measured
magnitude: duals agree with HiGHS to `1.73e-09`–`2.47e-09`, and the four methods disagree with each
other by only `2.5e-5` relative on an n=5000 LP at default tolerances (expl §2c, §7). Every frozen
tolerance in the Checks table is at least 100× the corresponding measured residual, so **no
comparison in this plan moves to a statistical criterion** — they all stay
deterministic-with-tolerance.

**Quantities that are genuinely not reproducible and are therefore never asserted on:**

| Quantity | Why it varies | How it is treated |
|---|---|---|
| `sol.get_solve_time()` → `report.runtime` | wall clock | reported, **never asserted** |
| `milp_stats["num_simplex_iterations"]` → `report.simplex_iterations` | search-order dependent | reported, **never asserted** |
| `lp_stats["nb_iterations"]` | method-dependent, and neither a simplex nor a barrier iteration count | **never reported and never asserted** |
| `lp_stats["dual_residual"]` | measured at `51.0` on a QP solved to optimality — meaningless under QP (expl §12) | **never reported and never asserted** |
| `milp_stats["mip_gap"]` | search dependent | asserted **only** as `is not None` (V1-4), never as a value |
| `sol.get_solved_by()` | routing decision | asserted **only** in V1-3, and only for the `Unset` (presolve) routing whose correlation was 6/6 exact over 144 cells. Its docstring states that a red means re-establish V1-2's coverage, never remove M2. |
| the exact objective of a `PrimalFeasible` / `FeasibleFound` termination | an unproven incumbent | only the **condition** is asserted (see the Status mapping table), never the objective |
| the pad row's dual | an artefact of a row linopy invented | sliced off before the solution is built (V1-6d asserts the slice, not the value) |
| **the 10 `y` components of `quadratic_model` and `quadratic_model_unbounded`** | Not solver nondeterminism but **model underdetermination**, which has the same consequence for a differential oracle: the objective is `x*x` only, so each `y_i` has zero cost, zero curvature, `lb=0` and `ub=+inf` ⇒ the optimal face is unbounded in `y` (`{x=0} × {y ≥ 10}` with `con0`, `{x=0} × [0,∞)^10` without it). Measured `method=3`: cuOpt `y = 155.97919941` vs HiGHS `y = 9.9999995`, **both optimal**; `\|Δy\| = 145.98`. Any solver, version or tolerance change may move it arbitrarily far. | **Never asserted against the oracle** — V1-6b and V1-13b compare the `x` block and the objective only. The shared suite takes the same position: `test_optimization.py:876` asserts `y.round(3) >= 10`, an inequality, and `test_quadratic_model_wo_constraint` (`:927-944`) asserts no `y` at all. A future row that compares `y` against HiGHS is a defect in the row, not in the solver. |

**One residual, stated rather than hidden:** the failure mode *past* the T4's memory ceiling is an
exploration Unknown. At `14231 / 15948 MiB` cuOpt degraded to `NoTermination` rather than raising
(expl §9), which this plan maps to `internal_solver_error`; a genuine CUDA OOM was never provoked.
No check in this plan asserts behaviour beyond the ceiling.
